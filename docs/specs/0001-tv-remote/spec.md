# SPEC-0001: macOS-пульт для TCL Android TV

Статус: Approved · Дата: 2026-10-28

## Зачем
Управлять телевизором TCL (Android TV) с Mac в той же локальной сети, не ища физический пульт.

## Решения
- Транспорт: ADB по Wi‑Fi (`adb connect <ip>:5555`, `adb shell input keyevent`). Почему — [ADR-0001](../../adr/0001-adb-transport.md).
- Поиск ТВ: Bonjour `_androidtvremote2._tcp` (сервис, который рекламирует каждое Android TV) + ручной ввод IP.
- Приложение нативное: SwiftUI, macOS 15+, без сторонних зависимостей.

## Требования
| ID | Требование | Проверка |
|----|-----------|----------|
| R1 | Пользователь вводит IP ТВ вручную; последний IP сохраняется между запусками. | `RemoteModelTests` |
| R2 | Приложение показывает ТВ, найденные в сети через Bonjour; выбор подставляет IP. | `DiscoveryTests` (парсинг адреса), вручную |
| R3 | «Подключить» выполняет `adb connect <ip>:5555` и показывает статус: подключено / нужно разрешить на ТВ / ошибка. | `ADBTests`, `RemoteModelTests` |
| R4 | Кнопки пульта: питание, домой, назад, D‑pad + OK, громкость ±, без звука, play/pause, перемотка назад/вперёд, источник сигнала, настройки. Каждая отправляет `input keyevent <код Android>`. | `ADBTests` |
| R5 | Стрелки клавиатуры, Return, Esc/Delete дублируют D‑pad, OK и «Назад». | вручную |
| R6 | Невалидный IP не передаётся в `adb` (это граница доверия: строка от пользователя попадает в аргументы процесса). | `ADBTests` |
| R7 | Ошибки `adb` (не установлен, ТВ офлайн, не авторизован) показываются в статусе, приложение не падает. | `ADBTests`, `RemoteModelTests` |

## Вне рамок (осознанно не делаем)
Ввод текста, запуск приложений, несколько ТВ одновременно, встроенный ADB без внешнего бинарника, App Sandbox / публикация в App Store.

## Предусловия (один раз на ТВ)
Настройки → Об устройстве → 7 раз нажать «Сборка» → Для разработчиков → включить «Отладка по USB» и «Отладка по сети» (если пункт есть). При первом подключении на ТВ нажать «Разрешить» (лучше с галочкой «Всегда»).
На Mac: `brew install android-platform-tools` (уже стоит).
